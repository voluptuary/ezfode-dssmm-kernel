## Last played title trace and preservation contract

Call path: `Launcher_GetStartGameEntry` → `Launcher_StartGetLastTitle` → `Launcher_CleanTitle` → `Launcher_DrawStartLastTitleEx`. The selected single-line branch uses the full `title` buffer, NOT the temporary `lines[0][32]`; copying that temporary into the marquee path would introduce real truncation. `Launcher_UpdateStartTitleScroll` runs while selected item is zero, waits 40 frames, then advances every eight frames. `Launcher_StartTitleShouldScroll` enables scrolling only for one-line layouts.

Direct extracted-function comparison verified `Launcher_StartGetLastTitle`, `Launcher_SplitStartTitle`, `Launcher_StartScrollTextLine` and `Launcher_StartTitleShouldScroll` are byte-identical from df346b5 to 6d6084e. In local HEAD the latter three are also identical; the getter increases `recent_name` from 200 to 256 bytes. Preserve that local improvement. There is no evidence that these v8 functions introduced the reported other-build regression.

Existing limits explain plausible symptoms to check against that build, without alleging a new local regression:

- `Launcher_CleanTitle` uses a 128-byte temporary, removes the final extension and parenthesized/bracketed annotations. Start calls it independently of Clean list; missing `(USA)` is cleaning, not necessarily clipping.
- Start draw and should-scroll functions each use `title[96]`: bytes discarded before marquee cannot later scroll into view.
- Static wrapping takes up to 18 **bytes** per line, at most three lines, then ellipsizes. A two-line layout subsequently drops a third generated line. Multi-line layouts never scroll in the existing predicate.
- Marquee indexing uses `strlen` and byte offsets, while overflow detection uses visible text length. Multibyte text can split between bytes. A theme changing from one line to two/three changes exposure of the title even without changing the filename.
- Inspect the other build for shortened recent-entry storage, accidental use of ellipsized/32-byte presentation strings as source, suppressed Start-loop scroll ticks, reset-on-every-frame, or altered theme width/line macros. No such cause is established here.

Safe optional full-name design, for a separate implementation decision: retain an immutable canonical filename from the existing resolver, sized to its supported bound and NUL-terminated. Derive a display string separately; do not mutate launch path, recents, favourite keys or artwork stems. Preserve the Clean list UI, parser, serializer and both settings values. Keep current Start cleaning semantics by default; if literal extension/region text is desired, expose that as a deliberate display policy rather than silently changing existing behavior. Define “full name” as either the complete cleaned title or complete literal filename in acceptance tests.

Use existing `DrawText12VisibleLength`, `DrawText12ByteOffsetForGlyphs` and `DrawText12CopyVisible` to advance whole renderer-supported glyphs, not arbitrary UTF-8 assumptions. Keep a complete display source through the render pipeline; an ellipsis is only an unselected viewport rendering. For single-line selected titles, use bounded glyph windows, current initial dwell/rate, and a gap or endpoint pause. For multiple lines, glyph-aware word wrapping should page/scroll remaining lines after a dwell if all text cannot fit; static wrapping alone cannot promise a full name. Cache title state on entry/source/favourite change rather than repeated storage reads per frame. Allocate bounded state in EWRAM only after checking budget; reset on actual source/selection changes. Preserve marker underlays when text animates during corner motion.

## Memory, alignment, size and ownership gates

`pReadCache` is 0x20000 bytes and has several incompatible owners. Bounds alone do not prove lifetime safety.

| Region/resource | Owner / consequence |
| --- | --- |
| cache [0,480) | `Clear` fill line; never keep live audio/persistent art here. |
| cache [0x200,0xA00) | 2048-byte temporary ring tile generation. Distinct from fill line, but overlaps other scratch users. Copy to OBJ VRAM before ROM/save work. |
| cache [0x1000,0x2000) | New boot-only settings snapshot; deactivate before artwork or writer reuse. Not required for presentation. |
| cache [0x10000,0x19060) | 168x110x2 Start popup underlay; overlaps thumbnail banks and save-art storage. No thumbnail reload while relying on it. Rebuild/invalidate affected caches afterward. |
| cache +0x10000 | Save artwork raw BMP: title 120x80x2 +54 =19254 bytes (ends 0x14B36); confirm alternate source style read size as well. Thumbnail banks elsewhere also share upper cache. |
| cache [0x18000,0x18C00) | Scaled 48x32x2 save artwork, 3072 bytes. Draw completely before Save_savefile; do not redraw from this region after SRAM/file buffers reuse it. |
| entire cache / lower banks | ROM load/patch, save read/write, FAT and list caches reuse scratch. Preserve local transaction/error behavior and cache invalidations. |
| dedicated audio buffer | 8192 bytes, aligned(4). Compressed launch header declares 8160 decoded bytes, matching select_raw_len; leaves 32 bytes capacity. Assert decoded size and padded length before accepting replacement assets. In-place playback bypasses memset/copy: future non-16-byte clips need explicit zero tail/padding. |
| startup audio | `UIAudio_PrepareBuffer` long-clip branch returns original const sample pointer in BOTH baseline and v8, not cache. Shared-buffer stopper only stops actual shared playback. Verify linked sample alignment, FIFO tail safety, DMA address and ROM bank lifetime; misleading legacy comments are not proof of current cache ownership. |
| spinner hardware/state | Reserves OBJ VRAM [0x06017800,0x06018000), all OAM snapshot, palette bank 15 at 0x050003E0; saves display register and full IntrTable. Snapshot fixed arrays use 3104 bytes before display/IRQ fields. Dedicated EWRAM required; prove no patch/compositor/emulator overlap. Full-table restore can overwrite legitimate handlers installed while active. |
| Start motion | Four corner pixel saves =1152 bytes plus coordinate metadata; complete state approximately 1444 bytes with 32-bit ints. EWRAM ownership must persist for Start lifetime and pointer must be initialized/cleared correctly. |

Alignment: `pReadCache` is a u8 array with section placement; offsets divisible by four do not independently prove base alignment. Verify symbol address in ELF/map or add explicit alignment in a later implementation. BMP pixel payload at +54 is halfword-aligned, not word-aligned; do not introduce u32 loads or DMA32 assumptions there. Popup row transfers are 336 bytes but source/destination positions still need halfword/word-aware copy selection. Compressed select/splash arrays explicitly align to four. Splash decoded size is 0x12C00 (76800), exactly 240x160x2, and writes VRAM via BIOS SWI 0x12; check ARM/Thumb SWI encoding with the actual build/disassembly.

Stack: `Launcher_LoadSaveArtwork` alone declares 104+104+256+200+512 =1176 bytes of character arrays before locals/callees. Save popup name adds 328 bytes of strings; Start title getter includes 256-byte path and current 256-byte name. Request compiler stack-usage output and inspect nested FatFs/artwork/text calls and IRQ headroom. Upstream moves many globals and FatFs scratch arrays into EWRAM; those moves may relieve IWRAM but consume scarce EWRAM. Do not assume upstream memory placement fits Merkin's additional caches. Review map, ROM size, linker limits and worst stack path for every target/theme.

Save artwork lookup first tries CUSTOM stem, then `.sav` matching last-played GBA header, and saves/restores GAMECODE. Adapt this to local manifest/long-name lookup rather than replacing local policy. BMP validation checks only part of the header; validate full dimensions, planes, bpp, compression, pixel offset and read extent before drawing. Signed negative height is accepted upstream: verify orientation handling rather than assuming it is correct. Art lookup uses global gfile; serialize and close it before save writer. Never introduce artwork I/O during pending SRAM transfer or inside an IRQ.

Ring teardown must precede every error screen, menu redraw, emulator handoff and reset. The VBlank handler only changes OAM/palette, but replacing the existing handler can suppress other required services. Check interrupt enable/IME, audio Timer1 behavior and full-table restore against local IRQ setup. Fade uses DMA3 and commits a terminal-color framebuffer; it restores BLDCNT but zeroes BLDY rather than restoring its previous value. Test blend/register state on failures and custom themes.

## Validation plan and evidence limits

Executed: git object/diff inspection, current-source tracing, source-tip comparison, and exact function-body hash comparison described above. No production edits, build, host test execution, emulator run or hardware test was performed for this documentation-only review. Hardware outcomes below are acceptance gates, not claimed results.

1. Filename preservation: capture current Merkin behavior first. Test 18/31/32/95/96/127/128/199/200/255-byte boundaries, spaces/no spaces, parentheses/brackets, extension dots, supported multilingual glyphs and missing recents. Compare one/two/three-line themes, selected/unselected, favourite cycling and rapid navigation. Require all intended display glyphs eventually visible for optional full-name mode, no broken glyphs, and identical launch target/art lookup. Clean list Off and On must persist across reboot and retain their list behavior.
2. Popup/motion: light/dark/custom assets, all row counts, save-type partial redraw, cheat return, A/B/Select timing, held/repeated keys, retarget during each easing frame, marker-off/alternate shapes, redraw while text scrolls. Require no stale pixels or lost input.
3. Startup/audio: cold/warm boot, slow/absent SD, FW-update prompt, boot targets, quicklaunch held key, sounds Off/On, pending save and invalid settings. Require visible errors despite forced blank, no artificial audio wait, clean audio finish into menu where no later sound/hardware operation interrupts it, no FIFO noise.
4. Launch: SD clean/addon, emulator paths, NOR, Start, list/list-art/horizontal/vertical, icon/missing/title/box/custom art; fast load (<6 frames), slow load, oversized/missing/bad ROM and patch failure. Require correct ring anchor, responsive IRQ/audio, restored OAM/palette/display/handlers on failure and no ring/register leak into game.
5. Save: auto/manual save, A/B, every supported SRAM/save size including banked saves, missing CUSTOM art, malformed/short BMP, missing/mismatched last ROM, long names, write failure/full/read-only SD. Verify exact saved bytes and pending-save flag retained on failure; no art read after writer starts. Use controlled copies of save data for destructive hardware failure tests.
6. Build/memory: build all supported local variants; compare map and size, verify alignment and memory range assertions, inspect stack usage and SWI/DMA instructions. Run relevant existing host suites (`savefile-host.c`, `fat-table-builder-host.c`, `fatfs-long-name-host.c`, `custom-manifest-host.c`, settings readers/enums/navigation, artwork draw/border and carousel motion). These suites alone do not establish DMA/IRQ/VRAM correctness; use emulator instrumentation and physical Omega DE testing.
